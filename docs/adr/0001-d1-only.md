# ADR-0001: D1 for all data

- **Status:** Accepted
- **Date:** 2026-10-02
- **Brief refs:** PRODUCT-BRIEF §2 goal 1, §8 Storage, FO-4, TP-3 (the brief's §8 lists this decision as "0004 (D1)")

## Context

Anjuna runs entirely on Cloudflare. It holds leads with PII, consent evidence, click sessions, postback and conversion state, factory state (templates, brands, installs, receipts, audit log) and control-panel auth. V1 kept all of this in D1 and has handled about 1,000 production leads. The factory also produces large immutable files: sealed template builds, the versioned form bundle and certification screenshots. Those do not belong in a database.

## Decision

1. **D1 is the only store for data.** Three databases per tenant:
   - `leads`: the V1 schema and migrations, ported, plus `brand_runtime`, `mailing_outbox` and the experiment/variant/keyword columns. `conversion_uploads` stays identical to V1.
   - `factory`: templates, versions, certifications, form_artifacts, brands, revisions, installs, receipts, audit_log.
   - `auth`: better-auth tables.
2. **R2 is allowed only for artifacts:**
   - sealed template versions (immutable, addressed by SHA-256) and the versioned form bundle (`form@sha` with its SHA-256 manifest);
   - certification evidence (lint/identity-scan output, Browser Rendering screenshots).

   D1 holds the metadata and hashes that point at these objects.
3. **Lead data never goes to R2.** No PII, consent evidence, click sessions, postbacks, conversions or exports of them are written to R2, not even temporarily.
4. Only the core Worker binds the `leads` database. Brand Workers have no D1 binding; they reach lead data only through core RPC (ADR-0003).

## Consequences

- One query surface and one backup/retention story for PII (retention periods: brief Q2).
- Lead writes use D1 batches so the lead, click claim, continuation and mailing outbox row commit together (V1 parity).
- D1 size and write limits apply. A per-tenant `leads` database is well within them at current volume; revisit only if real volume says so.
- Artifact objects in R2 are immutable; a new version is a new key, never an overwrite.
- Aggregated telemetry and funnel counts go to Analytics Engine (brief §8). They carry no PII and are not a system of record.
- Any proposal to put lead data anywhere other than core's D1 needs a new ADR that supersedes this one.
